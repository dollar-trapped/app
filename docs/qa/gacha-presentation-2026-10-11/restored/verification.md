# Blender 케이스·10개 낙하 빛 복원

- 사용자 피드백에 따라 기존 자체 제작 Blender 케이스 24장을 복원했다. 원본 생성 스크립트는 `tool/gacha_art/render_case.py`다.
- 보상 하나마다 낙하 광원과 꼬리 하나를 배치했다. 1회는 1개, 10회는 10개이며 High/Low에서 동일하다. 충돌 직전에 한 지점으로 모이고 케이스는 하나만 열린다.
- 개방 광선도 실제 보상 개수와 등급에 맞춘다. 서버 결과 순서·확률·지급·스킵 결과는 유지한다.
- 전체 Flutter 테스트 274개와 변경 영역 정적 검사 통과. 빛 간격·합류 위치, 원본 이미지 24장 디코딩, 비동기 로딩 중 화면 종료 시 해제도 검증했다.
- Rare/Special은 반전 전 동일한 낙하 색을 유지한다. 기존 실제 Canvas 픽셀 비교 검사도 통과했다.

실제 production painter를 420×900으로 출력한 장면:

[10개 빛](ten-lights.png) · [닫힌 Blender 케이스](blender-closed.png) · [열린 Blender 케이스](blender-open.png)

이 이미지는 Flutter 렌더 검토 자료이며 기기 캡처나 성능 측정이 아니다.

## 실기기 확인

SM_F966N 외부 화면 1080×2520, profile, Impeller/Vulkan. `com.dollarmullim.app.preview`에서 오프라인 확정 보상으로 검사했다. 세 경우 모두 실제 시계의 종료, 케이스 24장 로드, 보상과 빛 개수 일치, 예외 없음을 확인했다.

| 시나리오 | 프레임 수 | build p99 ms | raster p99 ms | raster 최대 ms | raster 16.67ms 초과 |
|---|---:|---:|---:|---:|---:|
| COMMON 1회 High | 542 | 1.737 | 2.777 | 5.280 | 0 |
| SPECIAL 10회 High | 1943 | 2.493 | 7.145 | 21.345 | 6 |
| SPECIAL 10회 Low | 1942 | 1.996 | 7.134 | 22.082 | 6 |

[원본 측정](profile.json). 세 경우의 p99는 16.7ms 이내다. 일부 개별 프레임 초과가 있으므로 고정 60fps를 보장하는 수치로 표현하지 않는다. 이번 측정은 세 시나리오에 한정하며 모든 장식 조합·iOS·펼친 화면을 검증한 것은 아니다.

초기 시도는 앱 시작 직후 고정 시간 대기가 실제 완료 시점보다 먼저 끝나 실패했다. 실제 컨트롤러 완료를 제한 시간 안에서 기다리도록 측정 코드를 수정한 뒤 재실행했고 위 세 경우가 통과했다. 시계를 강제로 진행하거나 스킵하지 않았다.
