# 장식 시스템과 확장 정책

## 의존 방향

`gacha`, `inventory`, `chat`, `profile`이 `cosmetics`의 모델과 렌더링을 사용합니다.
`cosmetics`는 이 기능들을 import하지 않습니다. 보관함은
`CosmeticInventoryRepository`의 조회·장착 기능만 사용하며, 뽑기 화면 이동은
호출자가 전달하는 콜백으로 처리합니다.

- `models/`: 아이템, 장착, 보유 정보 및 채팅 저장 시점의 외형.
- `rendering/effect_registry.dart`: 슬롯별 허용 토큰과 앱 내부의 타입 있는 효과 설정.
- `rendering/effects/`: 효과 종류별 구현. 여러 색상 조합은 같은 GradientEffect를 사용.
- `rendering/cosmetic_motion.dart`: 애니메이션 수명과 움직임 줄이기 설정.
- `widgets/`: 채팅·프로필·보관함·확률 목록에서 공유하는 표시.
- `preview/`: 기존 화면 설계용 표시 정의. 운영 획득 확률 화면에는 서버 아이템만 표시합니다.

아이템 ID와 효과 토큰은 서로 다른 개념입니다. 여러 아이템이 같은 효과 구현을
사용할 수 있습니다. 서버는 등록된 토큰만 선택하고, 속도·중력·색상 배열 등의
임의 렌더링 파라미터나 코드는 내려주지 않습니다.

## 확정한 운영 기준

1. 시각적 표현 규칙의 일관성을 우선합니다. COMMON은 단순 정적 표현,
   RARE는 그라데이션·패턴·특수 글꼴 등 복합 정적 표현,
   SPECIAL은 시간에 따라 변하는 동적 표현입니다. 기존 아이템도 재분류합니다.
2. ID·보유·장착 상태는 유지합니다. 선명한 주황/깊은 보라는 COMMON,
   손글씨는 RARE로 변경합니다. 진홍/황금빛/금박은 동적 SPECIAL을 유지합니다.
3. 등급 확률 70/25/5와 등급별 중복 보상 1/3/5칩을 유지합니다.
   변경 이후 중복 보상에는 변경된 등급이 적용됩니다. 이미 지급된 칩은 회수하지 않습니다.
4. 과거 채팅 snapshot과 과거 뽑기 결과의 rarity/appearance/보상은 수정하지 않습니다.
   앱은 현재 카탈로그·인벤토리와 과거 스냅샷을 각각 서버 응답대로 표시합니다.
   아이템 ID를 이용해 과거 기록을 현재 등급으로 덮어쓰지 않습니다.
5. 신규 RARE는 정적 gradient/pattern으로 확장합니다. 신규 SPECIAL은 고유 동적
   효과가 완성되고 작은 채팅 크기와 움직임 줄이기 검증을 마친 뒤 활성화합니다.
6. 활성 아이템 수를 기준으로 매번 개별 확률을 재산출합니다. UNIFORM일 때
   등급 확률 ÷ 해당 등급의 drawable 수를 사용합니다. 종류/등급 UI 필터는 분모를 바꾸지 않습니다.
7. 서버가 활성화한 NAME_COLOR/NAME_FONT/NAME_BACKGROUND만 추첨 대상으로 셉니다.
   새로운 슬롯/가중 추첨 도입 시 서버 계약과 앱 확률 표시를 함께 개정해야 합니다.

운영 반영 현황과 서버 요청은 [재분류 적용 명세](rarity-reclassification.md)를 참고합니다.

## 확정된 신규 효과 응답 계약

서버 배포 b691e97의 `styleToken` 계약을 사용합니다. 종류별 값과 styleToken 중
정확히 하나만 설정됩니다. nameColor에는 #RRGGBB만 넣으며, 효과 아이템에서는 null입니다.
기존 폰트와 배경 토큰도 유지합니다. 새로운 스타일은 별도 토큰으로 표현합니다.

카탈로그·인벤토리·뽑기 결과의 아이템:

```json
{
  "id": "color_sunset",
  "type": "NAME_COLOR",
  "displayName": "노을빛",
  "rarity": "RARE",
  "isDrawable": false,
  "appearance": {"nameColor": null, "nameFont": null, "nameBackground": null, "styleToken": "sunset_gradient"}
}
```

채팅 저장 시점의 슬롯:

```json
{
  "nameColor": {
    "id": "color_sunset",
    "rarity": "RARE",
    "color": null,
    "styleToken": "sunset_gradient"
  }
}
```

배경도 아이템의 `appearance.styleToken`, 채팅의
`nameBackground.styleToken`을 사용합니다. 효과 장식의 기존
종류별 값은 null입니다. 구버전 앱은 토큰을 무시하고 기본 닉네임으로 표시합니다. 구버전 배포 바이너리 호환은 실기기로 검증해야 합니다.

앱이 모르는 토큰 또는 슬롯과 맞지 않는 토큰은 전체 기본 닉네임으로 표시합니다.
기존 색상 HEX, 글꼴, 배경은 토큰이 없어도 종전대로 렌더링합니다.
새 토큰의 이름이나 의미를 기존 토큰에 덮어쓰지 않습니다.

## 새 아이템 추가 절차

1. 기존 효과 재사용 여부를 결정하고, 필요하면 효과 구현을 추가합니다.
2. 레지스트리에 슬롯별 토큰과 타입 있는 설정을 등록합니다.
3. 개발 테스트에서 작은 화면·색상 조합·움직임 줄이기를 확인합니다.
4. 서버에서 기존 아이템·스냅샷을 수정하지 않고 신규 ID와 토큰을 등록합니다.
5. 앱을 먼저 배포하고 소수 아이템만 활성화합니다. 초기 RARE 후보는 노을빛(sunset_gradient), 민트 격자(mint_lattice)입니다.
6. 조회·뽑기·장착·채팅 스냅샷·중복 보상·확률을 검증한 뒤 확대합니다.

weight를 도입하면 지금의 `등급 확률 ÷ 해당 등급 대상 수` 표시는 더 이상 맞지
않습니다. 서버 확률 응답과 앱 안내를 함께 변경한 후 활성화해야 합니다.

## 기존 SPECIAL 외형 업그레이드

진홍·황금빛·금박은 동적 효과가 있어 SPECIAL을 유지합니다. 작은 채팅에서도
변화가 인지되도록 광택 대비와 맥동을 보강하며, 금박에는 정적 금속 결을 함께 표시합니다.

- 금박: `gold_foil_shimmer` (NAME_BACKGROUND). 금색 고정 그라데이션 위로
  4초마다 낮은 밝기의 광택이 한 번 지나갑니다. 약 1.8초 이동 후 쉬며 반복합니다.
- 황금빛: `golden_shimmer` (NAME_COLOR). 짙은 금색 글자 그라데이션과 4초 주기의 광택.
  운영 카탈로그 v4에서 cos_color_special_01의 nameColor=null, styleToken=golden_shimmer를 확인했습니다.
- 진홍: `crimson_pulse` (NAME_COLOR). 짙은 적색 그라데이션이 4초 주기로
  천천히 약해졌다 밝아집니다. 빨간색 전체 아이템에 적용하지 않습니다.
  운영 cos_color_special_02는 SPECIAL이며 crimson_pulse를 사용합니다.

서버에서 업그레이드할 기존 ID를 확인한 후 현재 appearance를 styleToken 방식으로
전환합니다. 같은 행의 기존 nameBackground/nameColor 값은 null이어야 합니다.
구버전에서는 해당 장식이 기본 모습으로 표시됩니다. 새 채팅에는 해당 토큰을 스냅샷으로 저장합니다. 과거 메시지·뽑기 결과는
재작성하지 않습니다. 토큰 없는 과거 금박은 기존 단색 그대로 표시합니다.

운영 획득 확률 화면에서 디자인 후보와 시안은 모두 제거했습니다. 서버가 등록한 실제 추첨 대상만 표시합니다.
운영 카탈로그 v4에는 황금빛·진홍·금박의 토큰이 모두 연결됐습니다. 새 앱에서는 서버 조회 결과로 적용합니다.
기기나 미리보기의 움직임 줄이기 설정에서는 움직임이 정지합니다.

## 오로라와 별빛 물결 구분

같은 움직이는 그라데이션의 색상 변형 대신, 기존 `aurora`와 `starlight` 토큰에
각각 별도 장면을 렌더링합니다. 서버 응답 계약과 아이템 ID는 유지됩니다.

- 춤추는 오로라: 어두운 고정 배경 위에서 넓고 반투명한 청록·보라 빛의 띠가
  위아래로 휘어 움직입니다.
- 별빛 물결: 어두운 고정 배경 위에서 가느다란 수평 물결이 오른쪽으로 흐르고,
  작은 빛점이 물결을 따라 이동합니다. 기존 별밤의 별 입자와 구분됩니다.

두 장면은 4초 주기로 반복하며 닉네임 배경 안으로 잘립니다. 움직임 줄이기 또는
비활성 화면에서는 애니메이션이 멈추고 정적인 장면을 표시합니다.
