# 계정별 누적 10회 보장 앱 연동

## 기능 판별

`GET /api/v1/cosmetics`의 `drawPolicy.cumulativeGuaranteedRareOrAbove=true`일 때
누적 보장 안내를 표시한다. 버전 번호로 기능을 추정하지 않는다.
누적 정책이 아니고 `batchGuaranteedRareOrAbove=true`이면 기존 10회 묶음 안내를 표시한다.
두 필드가 없으면 보장 기능을 가정하지 않는다.

누적 정책은 단뽑·배치의 연속 COMMON 횟수를 공유하며 RARE/SPECIAL이면 중복 여부와
무관하게 초기화된다. 9회 연속 COMMON 이후 다음 결과는 RARE 이상이다.
기본 등급 확률은 그대로이며 보장 추첨에서는 RARE:SPECIAL 기본 가중치 비율을 유지한다.

## 상태 조회와 응답

`GET /api/v1/users/me/cosmetics`, 단뽑 응답, 배치 전체 및 각 결과의 최상위 필드:

```json
{"consecutiveCommonCount":7,"drawsUntilGuaranteed":3}
```

앱은 정수 카운터 0..9와 남은 횟수 `10 - 카운터`를 함께 검증한다.
누락·불일치는 알 수 없는 상태로 처리하며 0회로 대체하지 않는다.
과거 저장 응답에는 해당 필드가 없어도 기존 결과를 파싱할 수 있다.
배치의 각 결과는 순번 직후 상태이고 전체 응답은 완료 상태이므로 별도로 보존한다.

현재 횟수 표시는 내 장식 GET을 기준으로 한다. 결과 화면 종료 후 기존 조회 흐름에서
카탈로그와 내 장식을 다시 조회한다. 과거 멱등 재응답의 카운터를 현재 상태에 적용하거나
앱에서 추첨 등급으로 카운터를 계산하지 않는다. 조회 중·실패·필드 누락 상태에서는
확정 횟수를 표시하지 않는다. 달러칩 교환 중 보유 정보를 갱신할 때 카운터를 보존한다.

## 표시

- 남은 횟수 1: `다음 뽑기 레어 이상 확정`
- 남은 횟수 2..10: `레어 이상 보장까지 최대 N회`
- 안내: `단뽑·10회 뽑기 누적 횟수 공유`
- 확률 안내: 기본 추첨 확률과 누적 보장 적용 조건을 구분한다.

## 검증 범위

`test/cumulative_draw_guarantee_test.dart`에서 정책 구분, 과거 응답 호환,
카운터 경계·누락·불일치, 순서별 배치 스냅샷 및 단뽑/배치 멱등 결과 확인 후
최신 GET 상태 표시를 검증한다. 서버 추첨·DB 트랜잭션 검증은 서버 테스트 범위다.
운영 게시와 실기기 렌더링 검증은 이 앱 연동 작업에 포함하지 않는다.
